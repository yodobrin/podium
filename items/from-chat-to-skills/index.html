Part 1 · The Words We HearDeep Dive

Deep dive Deep

Buzzwords, decoded: the model

Most confusion comes from mixing up the model with the app around it.

LLM

Large Language Model. The engine type behind GPT, Claude and Gemini: a very large next-token predictor.

Prompt

Everything you send in: your question plus any instructions and files. Better input, better output.

Context window

How much text the model can see at once. Past the limit, older content is dropped or summarized.

Hallucination

A fluent, confident answer that is wrong. A side effect of predicting plausible text, not looking up facts.

Fine-tuning

Extra training on your own examples to change the model's behavior. Expensive; skills and grounding are usually the cheaper first step.

RAG & embeddings

Embeddings turn text into numbers that capture meaning. RAG uses them to find relevant documents and paste them into the prompt.

Part 1 · The Words We HearDeep Dive

Deep dive Deep

Buzzwords, decoded: acting

The more an AI can do on its own, the more guardrails it needs.

Tools

Functions the model can ask the app to run: search the web, read a file, send an email. The model asks; the app does.

MCP server

Model Context Protocol: a standard plug for tools and data. Build one server and any compatible app can use it.

Agency

How much the AI decides and does on its own. Low: it suggests. High: it plans, acts and checks without you.

Agentic

Describes a system that loops: plan, use a tool, read the result, revise. More agency, more autonomy.

Multi-agent

Several agents with separate roles, for example one researches and one reviews, passing work between them.

Guardrails & human in the loop

Limits on what the AI may do, plus approval points where a person confirms before anything irreversible.

Part 2 · The Chat WindowOverview Mode

What OOB chat struggles with

The failure patterns everyone recognizes

The model is general. Your work is specific. You spend 10 minutes re-establishing context, then throw it away.

  • Doesn't know your terminology, your style, or your constraints
  • Forgets everything the moment you open a new chat
  • Re-explaining the same context over and over
  • Confidently wrong when it has no grounding
  • Each person on your team gets a different quality of answer

Why this happens

Each chat is an empty room. The model walks in with no idea who you are or what good looks like for you.

Part 3 · The Chat WindowOverview Mode

Vocabulary

Grounding means answering from evidence

Grounding turns "sounds right" into "is backed by this source".

Without grounding

  • Answers from training memory only
  • Fills gaps with plausible guesses
  • Nothing you can check

With grounding

  • Reads your real material first
  • Answers from what it just read
  • Can point to the source

Where grounding comes from: your files and documents, web or database search, tool output, and written instructions or reference material.

Part 3 · Equipping the ModelDeep Dive

Deep dive Deep

Anatomy of a skill

If you can brief a new hire in a page, you can write a skill.

A minimal SKILL.md

---
name: meeting-synthesizer
description: Turn meeting notes
  into structured summaries with
  decisions and action items.
---

# Workflow
1. Extract decisions, actions, risks
2. Group by owner
3. Flag anything ambiguous

# Do not
- Invent action items
- Guess owners when unclear
  • Trigger: description tells the model when to use it
  • Workflow: the steps you'd walk a new hire through
  • Boundaries: mistakes you've seen often enough to name
  • Examples: optional, but transform output quality
  • Tools: optional scripts the skill can call

Part 6 · The ComparisonDeep Dive

Deep dive Deep

What the skill actually does

If the skill is wrong, you fix it once. In the chat flow, every mistake is an unknown number of future mistakes.

The run, step by step

  1. Trigger phrase matches the skill's description
  2. Tool loads the SKILL.md into context
  3. Model follows the workflow: extract, group, flag
  4. Output lands in deliverables/meetings/YYYY-MM-DD/
  5. You review the diff, not the whole document

What changed

  • The 10-minute re-brief is gone
  • Format is now a review, not a rewrite
  • Teammates get identical quality on the same task
  • Mistakes become single-point fixes

Part 8 · The Honest ViewOverview Mode

The honest tradeoffs

Skills are not free

You trade upfront discipline for durable, repeatable output. That's the only trade.

What you give up

  • Time upfront, writing things down
  • Discipline: a stale skill is worse than no skill
  • Some creative wandering: chat is better for exploration
  • Simplicity: a folder is one more thing to maintain

What you get back

  • Repeatable quality on recurring work
  • Context that compounds across sessions
  • Something you can hand to a teammate or successor
  • Portability across AI vendors
Part 8 · The Honest ViewDeep Dive

Deep dive Deep

When not to build a skill

If you've done the task three times and will do it three more: write a skill. Below that, chat is the right tool.

  • You're exploring, not operating: chat is better
  • You'll run this once a quarter: not worth writing down
  • The task has no stable "what good looks like" yet
  • Vendor-provided defaults already do 90% of it
  • You can't articulate the workflow: write it as prose first

Rule of thumb

If you can't yet describe what good output looks like, you're not ready to write a skill.

Keep exploring. Write the skill when the pattern is stable.

Part 9 · Getting StartedDeep Dive

Deep dive Deep

Your first skill in 15 minutes

When the skill produces something wrong, change the skill, not the output.

The recipe

  1. Open a new folder. Create SKILL.md.
  2. Write a one-sentence description. This is the trigger.
  3. Write the workflow as if briefing a new hire: numbered steps.
  4. Add 2-3 lines under Do not. Mistakes you've seen.
  5. Paste one great example of the output.
  6. Run it. Fix issues by editing the skill, not the output.

Common mistakes

  • Writing the skill before doing the task: a guess, not knowledge
  • Trying to cover every edge case: start with the common one
  • Being vague ("be thorough"): be specific ("list three sources")
  • Skipping the "do not" list: your mistakes are the richest signal
